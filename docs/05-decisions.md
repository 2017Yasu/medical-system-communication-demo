## 未決事項

ID は欠番を詰めずに管理する（解決済みの O-01・O-02・O-05 は D-18・D-19・D-13 に移した）。

| ID | 論点 | 選択肢 | 判断材料 |
|---|---|---|---|
| O-03 | HAPI FHIR のバージョン | skeleton の 7.0.2 のまま / 最新安定版へ更新 | 更新する場合は API の変更点を確認する |
| O-04 | JSON Patch の実装方法 | 既存ライブラリを使う / 必要な操作（replace / add）だけ自作 | ライセンス・依存関係の大きさ |
| O-06 | 講演 1 回あたりの所要時間とシナリオの組み合わせ | 例：15 分（S1 + S2）、30 分（S1〜S3）、45 分（全部） | ステップ送りの粒度と解説パネルの分量に影響 |
| O-07 | 自習モードのガイドの作り方 | 画面上の吹き出しで案内 / 解説パネルに手順を表示 / 印刷した手順書を併用 | 展示ブースでの運用（説明員の有無） |
| O-08 | 講演時の画面レイアウト | ステージビュー 1 画面のみ / 外部モニタと併用 | プロジェクタの解像度、文字の大きさ |
| O-09 | FHIR Tester（testpage overlay）を残すか | 残す（`/tester/*` へ移す）/ 削除する | 技術者向けの説明に使うか。削除すると Spring 依存が減る |
| O-10 | 処方の MedicationRequest を `completed` にする時点と主体 | 払出時に薬剤部門システムが更新 / 更新しない | S4 の詳細化時に、薬剤部門の一般的な運用を確認して決める |

## 技術検証項目

実装の初期段階（スパイク）で確認する。

| ID | 確認内容 |
|---|---|
| V-01 | skeleton を R4 に切り替えてビルド・起動できること（`hapi-fhir-structures-r4`、`FhirContext.forR4Cached()`、Tester の `FhirVersionEnum.R4`） |
| V-02 | `@Patch` メソッドでも If-Match の版が `IdType` に渡されること（`@Update` では渡されることをドキュメントで確認済み） |
| V-03 | `@Transaction` で受けた Bundle の `entry.request.ifMatch` / `ifNoneExist` を取得して処理できること |
| V-04 | 組み込み Jetty 上で HAPI RestfulServer・Jakarta WebSocket エンドポイント・静的 UI の配信を同居させられること |
| V-05 | 静的 UI・FHIR（`/fhir/*`）・Tester（`/tester/*`）のパス割り当てが衝突しないこと（skeleton では Tester の Spring MVC が `/*` を使用している） |
| V-06 | ネットワークを切断した状態で、ビルド済みの Docker イメージから `docker compose up` で起動し、全シナリオを実行できること |
| V-07 | 2 つのブラウザウィンドウから同時に PATCH したとき、必ず片方が 412 になること（S2 の再現性） |
| V-08 | React の開発サーバー（Vite）からコンテナ上の FHIR サーバー・WebSocket へプロキシして開発できること |
