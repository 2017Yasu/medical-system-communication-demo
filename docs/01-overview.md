# 01. 概要

## 目的

電子カルテと部門システム（検査・放射線・薬剤）が FHIR Repository サーバーを介して連携する様子を、
**医療従事者にも分かりやすく**見せる。

伝えたい中心メッセージは次の 3 点。

1. **「依頼」と「作業の進み具合」は別物として管理する**
   ServiceRequest / MedicationRequest（認可・意図の状態）と Task（履行の状態）を分離する。
2. **オーダー・結果は「まとめて一括」、進捗は「小さく更新」**
   オーダー発行・結果返却は Transaction Bundle、進捗管理は Task の RESTful 更新、通知は Subscription（ハイブリッド方式）。
3. **同時操作の事故は仕組みで防ぐ**
   ETag / If-Match による楽観的ロック、Task.status + Task.owner による論理ロック、Slot の仮押さえ → 確定 → タイムアウト。

## 対象者

| 対象 | 期待する理解 |
|---|---|
| 医療従事者（医師・看護師・臨床検査技師・診療放射線技師・薬剤師・医療情報部門） | 業務の流れとシステム間でやり取りされる情報の対応、同時操作で起きる事故とその防止 |
| 医療情報システムの技術者 | 実際の FHIR リソース・HTTP リクエスト/レスポンス・JSON の中身 |

同じ画面で両方に応えるため、**業務用語の表示と FHIR 用語の表示を併記**する（[04-design-rules.md](04-design-rules.md#表示ラベル) 参照）。

## デモ形式

講演と自習の**両方**に対応する。

| モード | 想定場面 | 特徴 |
|---|---|---|
| 講演モード | 講演者がプロジェクタに映して説明 | 1 ステップずつ進める・戻す、解説パネル、大きめの文字、1 画面に複数システムを並べる「ステージビュー」 |
| 自習モード | 展示ブース・個人学習で来場者が操作 | ガイド付きツアー（次に押すボタンを案内）、各ステップの「いま何が起きたか」解説、いつでも初期化 |

## 実行環境

- **講演者のノート PC 1 台でオフライン実行**する。
- インターネット接続・外部 CDN・外部サーバーに依存しない。
- 起動・初期化は 1 コマンド / 1 クリックで行えること。

## 基本原則

1. **システム間の連携は FHIR サーバー経由のみ**
   電子カルテ画面と部門システム画面が直接やり取りする経路を作らない。デモで見える通信がすべてである状態を保つ。
2. **架空データのみ**
   実在の患者・医療機関・職員の情報は扱わない。氏名は明らかに架空と分かるものにする。
3. **すべての通信を見える化する**
   FHIR サーバーが受けたリクエスト / 返したレスポンス / 送った通知は、通信モニタに表示できること。
4. **「事故」を再現できる**
   正しい方式だけでなく、ルールが無い場合に起きる事故（Lost Update、二重予約）を意図的に起こせること。
5. **規格に忠実、ただし必要十分**
   FHIR R4 の仕様に沿うが、目的はワークフローの説明であり、プロファイル準拠や網羅的な API 実装は必要な範囲に留める。
6. **セキュリティ（認証・認可）はスコープ外**
   SMART on FHIR / OAuth 2.0 / IHE IUA は解説で言及するに留め、デモ実装には含めない。
